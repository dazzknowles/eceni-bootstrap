# Windows policy behaviour

The manifest mirrors the supplied Local Group Policy choices: Configure Automatic Updates is enabled with `AUOptions=3` (automatically download and notify for installation); automatic restart at the scheduled time is disabled; the custom restart-reminder schedule is disabled; auto-restart notifications are turned off; required-notification dismissal uses its disabled/default behaviour; and the legacy logged-on-user restart guard is enabled. The existing additional safeguards remain: compliance deadlines are disabled and the general update-notification display policy is left at its disabled/default behaviour.

The logged-on-user guard applies only to **scheduled installs (`AUOptions=4`)**; it is not an effective extra guarantee with option 3. Microsoft also marks the scheduled-time restart controls as legacy on Windows 11. Do not describe this combination as “Windows can never reboot automatically.” The bootstrap itself never initiates a restart. Microsoft's documentation distinguishes these policy behaviours: [Manage device restarts after updates](https://learn.microsoft.com/en-us/windows/deployment/update/waas-restart).

Apply writes supported-policy registry locations rather than creating local GPO objects. An existing domain/MDM/local policy can override them. Inspect actual Windows Update behaviour and effective management settings on the target. Pro/Enterprise/Education support differs from Home; policy entries are skipped with a warning on Home. No service, scheduled task, Defender or Update component is disabled.

Telemetry is set to Required on Pro and to the lowest policy level on Enterprise/Education/IoT. Optional/tailored experiences and advertising settings are disabled separately. Some consumer-content, suggestion and UI settings depend on Windows edition/build and can change in future updates. [Diagnostic-data policy documentation](https://learn.microsoft.com/en-us/windows/client-management/mdm/policy-csp-system#allowtelemetry) is the authority for edition support.

Recall's optional component is disabled if available and snapshot policy is set. Missing components are skipped. Click to Do is disabled with the user policy where the installed build supports it. The policy reference lists version and edition applicability: [Windows AI policy](https://learn.microsoft.com/en-us/windows/client-management/mdm/policy-csp-windowsai). The script verifies stored values, not unsupported features magically taking effect.

Removals match exact Appx names for the current user only. Protected packages are reported, not forcibly removed. Provisioned packages and other users are untouched. The profile leaves Solitaire and core utilities intact. Game Bar/Xbox removal is distinct from removing Store infrastructure.

Power settings use the current scheme and change only AC/DC display and sleep timeouts. Lid-close behaviour, hibernation, brightness and hardware power management are preserved. Fast Startup is a separate registry setting. Explorer is restarted at most once after changed current-user UI values, limited to the current session; set `RestartExplorer = $false` to apply the visual change at next sign-in instead.
